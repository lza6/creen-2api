## 2. 游客登录机制已失效 `已验证`

### 2.1 实测流程

```js
// 步骤 1：创建游客 —— ✅ 成功
POST /api/auth/createGuest
→ { code: "200", data: { guestUid: "1b200808-...", guestKey: "$2a$10$gOIHBD0h..." } }

// 步骤 2：游客登录 —— ⚠️ 返回成功但无 token
POST /api/auth/loginByGuest
   body: { authLoginByGuestRequest: { guestUid, guestKey } }
→ { code: "200", data: { idToken: null }, msg: "操作成功" }
```

### 2.2 关键观察

| 观察 | 证据 |
|------|------|
| **`idToken` 恒为 `null`** | 多次测试，无论是否带 `x-finger` 指纹 |
| **浏览器 localStorage 为空** | 访问首页 12 秒后，`localStorage` 无任何键 |
| **`/api/auth/check` 返回 401** | 说明未建立会话 |
| **用户注册也被拦** | `regSubmit` → 401（需先有会话） |

### 2.3 推断 `合理推断`

服务端**已关闭游客无感登录**（或需要额外的风控条件，如真实浏览器指纹 + Turnstile 通过）。

**这与前端代码的预期行为不符**：`6628` 的 `AuthProvider` 设计为"游客自动登录"，但服务端不签发 token，导致：
- 前端 `localStorage` 为空
- 所有需认证接口返回 401
- **普通用户必须注册才能使用**（生成类功能）

> 这可能是**反滥用措施**：早期版本允许游客直接生成（消耗资源），现在强制注册。

## 3. 无头浏览器的影响 `已验证`

| 配置 | 游客登录 | 页面渲染 |
|------|---------|---------|
| 无头 + 反自动化参数 | ❌ localStorage 为空 | ✅ 正常 |
| `createGuest` API | ✅ 成功（返回 guestUid/guestKey） | — |

> **结论**：无头模式**不影响 API 直调**，但前端 JS 的指纹初始化可能受阻（导致登录流程不启动）。

## 4. 实测方法（可复现）

```js
// 用工具驱动系统 Chrome，在页面上下文内直接调用 API
const res = await fetch("/api/aiVideo/models", {
  headers: { "x-platform": "web", "x-version": "999.0.0", "x-language": "en" }
});
```

**关键**：
1. 必须用**真实浏览器**（Node 直连被 Cloudflare 403）
2. 必须**在页面上下文内** `fetch`（携带 CF 会话 cookie）
3. 用系统 Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）
