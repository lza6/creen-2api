# Creen2API Constitution

> 本文件为此项目的最高规范。任何实现、审查、发布必须以此为准。
> 与 `CLAUDE.md` 或其它约定冲突时，本文件优先。

## Core Principles

### I. 真实闭环优先（NON-NEGOTIABLE）

每一处声称"已完成"的功能，必须同时具备：**可执行代码 + 可运行命令 + 可复现的验证证据**。
"理论可行"、"有代码片段"、"有界面按钮" 均不构成完成。Mock 只证明隔离逻辑，不得描述为真实集成已通过。
结论使用四级标签：`已验证`（实际运行观察）/ `静态确认`（读代码确认）/ `合理推断`（间接证据）/ `待验证`（缺环境或权限）。

### II. bun 运行时硬约束（NON-NEGOTIABLE）

本网关**必须**运行在 bun（≥ 1.1）之上。Node 原生 `https`/`http2` 的 TLS 指纹（JA3/JA4）会被上游
Cloudflare WAF 识别并返回 403。任何绕过此约束的尝试（自定义 TLS 栈、代理、curl 拼装）都属于
架构级变更，须先写 ADR 并经确认。`assertBunRuntime()` 启动守卫不可移除。

### III. 上游积分红线

生成端点会真实消耗上游账号积分（图像 1~45、视频 25~225 积分/次）。因此：
- 自动化测试**只允许**调用公开只读端点（models / calculateIntegral 等），不得默认触发 `create`。
- 禁止在 CI 中运行会消耗积分的测试；E2E 仅覆盖公开端点，且须可离线跳过。
- 新增压测、批量调用一律先评估积分成本并向用户申请预算。

### IV. 网关入口边界

网关代理的是**用户自己的付费账号**。任何对外可访问的部署**必须**配置 `gateway_api_key`；
默认监听 `127.0.0.1`。放宽监听地址或引入新公开端点，必须同步评估鉴权、限流与并发门控是否覆盖，
并在 README 的"安全"章节披露。

### V. 面板无构建链

`src/web/panel.ts` 内嵌单页 HTML/JS，**无前端构建步骤、无外部 CDN 运行时依赖**。
任何面板改动必须用真实浏览器或 node 语法校验 + 结构断言验证，不能只看字符串拼写。

### VI. 零运行时依赖

`dependencies` 必须保持为空（bun 内置 HTTP/fetch/TLS 已满足全部需求）。
引入任何运行时依赖需先论证不可替代性并写 ADR；`devDependencies` 仅限类型与工具。

### VII. 不重构、小步走

只做小步、可回滚、可单测的行为级改进。不"顺手"重构没坏的东西。
发现无关死代码时指出并说明，不静默删除。配置项一旦声明，必须被真实消费（不得留死配置）。

## 质量门禁

每次提交前必须全部通过：

```bash
bunx tsc --noEmit          # 类型检查（strict）
bun test test/unit         # 单元测试（无网络，必须全绿）
bun test test/e2e          # E2E：仅公开端点（需网络与 bun）
```

- 单元测试覆盖新增逻辑的正常 / 错误 / 边界路径。
- 测试数量须记录并在 README / CHANGELOG 中同步。
- 门禁未全绿不得宣称完成。

## Governance

- 本规范优先于其它开发约定；修订须说明理由、影响范围与迁移方式。
- 每次发布须核对：门禁通过、文档与真实行为一致、剩余风险已披露。
- 外部受限项（真实上游账号、付费额度、生产凭据、服务器运维）必须在交付说明中明确边界。
